## Overview
This skill is triggered whenever the user asks to execute one or more tasks that require planning and atomic commits. It creates a markdown plan, executes each task in order, and makes a separate commit for each task while respecting the project's commitlint configuration.

## Step‑by‑Step Instructions
1. **Create a plan file**
   - Generate a new markdown file (default location `docs/plans/PLAN-<YYYYMMDD>.md`).
   - Use the **Plan Template** below. The user may rename or relocate the file; the skill must keep track of its path.
2. **Read commitlint configuration**
   - Look for one of the following files in the repository root (in order):
     - `commitlint.config.js`
     - `commitlint.config.ts`
     - `commitlint.config.mjs`
     - `.commitlintrc.json`
     - `.commitlintrc.js`
     - `.commitlintrc.yml`
     - `.commitlintrc.yaml`
     - `package.json` (key `commitlint`)
   - If none is found, abort with a clear warning.
3. **Determine remote**
    - Run `git remote -v` and ensure the output is not empty. Parse the first remote (usually `origin`). If no remote is configured, abort with a clear message (e.g., "No git remote configured. Aborting — cannot commit without a remote.") and optionally suggest adding one with `git remote add origin <url>`.
4. **Execute tasks**
    - For each task, first check if it declares dependencies via a `depends:` field (e.g., `- [ ] Task B :: status: todo :: depends: Task A`). Only when all listed dependencies have `status: done` should the task be marked `in_progress`.
     - Update the task line in the plan to `status: in_progress`.
     - Run the task (the actual execution is external to the skill).
     - Upon success, update the line to `status: done` and check the checkbox (`- [x]`).
5. **Commit per task**
   - Build a commit message that complies with the loaded commitlint rules:
     - English, imperative mood.
     - No AI signatures, footers, or generated‑by notes.
     - Follow the type/scope/subject format defined by the project's config.
    - Determine the files changed by the task using `git diff --name-only` (or `git status --short`).
    - Stage **only** those files with `git add <files>` (or `git add -u` for modifications and deletions).
    - Run `git commit -m "<message>"`.
    - Validation with `npx commitlint --from HEAD~1 --to HEAD` (or the project's custom lint command) is OPTIONAL. If executed and it fails, display the error, amend the commit with `git commit --amend`, and re‑run validation before proceeding.
6. **Finalize**
   - When all tasks are marked `done`, generate a summary section at the end of the plan, listing each task, its commit SHA, and a link to the remote repository if possible.
   - Optionally push the commits (`git push`), but the skill does not force a push.

## Plan Template (copy into a new `.md` file)
```markdown
---
title: "<Plan Title>"
date: "<YYYY-MM-DD>"
---

## Phases (optional)
### Phase: <Phase Name>
- [ ] Task 1 :: status: todo
- [ ] Task 2 :: status: todo

## Tasks without phases (optional)
- [ ] Task A :: status: todo
- [ ] Task B :: status: todo
- [ ] Task B :: status: todo :: depends: Task A
```

## Commit Message Rules
- Must satisfy the project's commitlint configuration (type, optional scope, subject length, etc.).
- Language: English.
- Tone: Imperative (e.g., `feat: add user authentication`).
- No autogenerated footers, `Co‑Authored‑By`, or any indication of AI assistance.
- Keep the subject concise (≤ 72 characters) and body optional.
- Example: `feat(api): add login endpoint`

## Git / Commitlint Commands Used
- `git remote -v`
- `git add <files>` (stage changes)
- `git commit -m "<message>"`
- `npx commitlint --from HEAD~1 --to HEAD` (or the project's custom lint command)
- Optional: `git push`

---
*The skill works on Windows (PowerShell), macOS, and Linux. Ensure `git` and `npx` are available in the system PATH. For Windows, use PowerShell syntax (e.g., `git remote add origin <url>`). Adjust any Unix‑specific paths (e.g., `~/.config/...`) to their Windows equivalents (e.g., `C:\Users\<User>\AppData\Roaming\...`).*
